# Step 8.3: FastAPI + WebSocket Real-Time API

## Architecture
The real-time API wraps the frozen `StreamPipeline` logic in an asynchronous REST and WebSocket boundary, enabling external AWS stations to seamlessly stream telemetry into SkyGuard AI.

```ascii
[AWS Simulation / Live Data]
         |
    (POST /api/v1/observations)
         |
      FastAPI
         |
 [Per-Station asyncio.Lock]
         |
[StreamPipeline for Station ID]
         |
    (Result JSON)
         |
[WebSocket connection_manager] -> Broadcast to (/ws/{station_id})
```

## Endpoints

### 1. `GET /health`
Returns the status of the API without triggering ML inference.
**Response:**
```json
{
    "status": "ok",
    "service": "SkyGuard AI"
}
```

### 2. `POST /api/v1/observations`
Processes exactly one observation for a specified station.

**Request Schema:**
```json
{
    "station_id": "AWS_001",
    "timestamp": "2026-09-04T12:00:00",
    "temperature": 24.5,
    "pressure": 1002.3,
    "humidity": 71.2
}
```

**Response Schema:**
The exact JSON dictionary returned by `StreamPipeline`, augmented with the `station_id`.
(Contains `processing_state`, `anomaly_flag`, `fault_type`, `temperature_status`, etc.)

### 3. `GET /ws/{station_id}`
WebSocket upgrade endpoint for subscribing to real-time events.
Clients receive the exact JSON generated by `POST /api/v1/observations` each time a valid observation is processed for `station_id`.

## Station-Specific Pipeline State
`StreamPipeline` is natively stateful (it stores 360 minutes of rolling observations in a deque). The API maintains a global dictionary mapping `station_id` to its own isolated `StreamPipeline` instance.
- **AWS_001** does not leak statistical baseline data to **AWS_002**.
- Instantiations occur automatically upon receiving the first observation for an unknown `station_id`.

## Concurrency & Ordering
- **Concurrency**: Fast asynchronous requests can race. The API uses a per-station `asyncio.Lock()` wrapper around the `process_observation` method to ensure sequential, chronological insertion into the pipeline deque.
- **Ordering**: The API tracks the timestamp of the last processed row for each station. If an observation arrives with `timestamp <= last_timestamp`, it is immediately rejected with a `400 Bad Request`. The ML pipeline is strictly protected against out-of-order data corruption.

## Limitations
1. **In-Process State**: Pipeline instances and connection managers are stored in FastAPI application memory. A distributed, multi-pod Kubernetes deployment would require an external state store (e.g. Redis) and message broker (e.g. Kafka).
2. **Security Scope**: This is a prototype API; production authentication (e.g. OAuth2, API Gateway) is excluded by design.
3. **Database**: Historical persistence is not included in this pure real-time streaming prototype.

## Running Instructions

### 1. Start the API Server
```bash
python -m uvicorn api.main:app --reload
```
View automatic interactive docs at: `http://127.0.0.1:8000/docs`

### 2. Run the Real-Time Simulator/Demo
In a separate terminal, execute:
```bash
python api/run_api_demo.py
```
This connects to the WebSocket and simulates sending high-velocity observations through the REST endpoint, demonstrating the resulting broadcast.
